# Emulator path: differences from the original

This file lists each deliberate difference between the emu APK and v1 (the original game with the v1 patches). Each item gives the reason and the phase that added it.

| # | Difference | Reason | Phase |
|---|---|---|---|
| 1 | The bridge serializes each guest entry with one mutex (`bridge/src/bridge.cpp`). In v1, the GL thread and the UI thread call native code with no lock. | One core state cannot run on two threads at the same time. The order of calls stays the order of the threads. Only the data race of v1 goes away (`PLAN.md` DES-08). | E1 |
| 2 | A guest entry on a thread that is already inside a guest call stops the process with a crash report. | One core cannot run two guest calls on one stack. `E2` checks that no upcall does this (`PLAN.md` DES-08). | E1 |
| 3 | `fopen`, `stat`, `access`, `unlink` and `rename` refuse each path outside the files folder of the app. The guest gets `EACCES` or `ENOENT`, and the bridge writes a log line. | The guest can write only its own save files (`PLAN.md` DES-05). The guest uses only paths under `getAbsolueFilePath`. | E1 |
| 4 | `GetStringUTFChars` and `GetByteArrayElements` always give a copy in the guest Java heap, and they write `isCopy` = 1. | A 64-bit host pointer does not fit in a 32-bit guest pointer (`PLAN.md` DES-07). `ReleaseByteArrayElements` copies the data back for mode 0 and `JNI_COMMIT`. | E1 |
| 5 | The bridge writes log lines to logcat with the tag `ArelEmu`: the `printf` output of the guest, file access, method IDs and crash reports. In v1, the `printf` output of the guest goes nowhere. | Debug aid (`PLAN.md` DES-13). The game does not see it. | E1 |
| 6 | Debug builds write the file `arelemu-debug.log` in the app data folder (the parent folder of the files folder). It holds these lines: each guest entry from Java (not `NativeRender`), the first use of each `JNIEnv` slot, each upcall and its result, and each `RegisterNatives` entry. It also holds the Gold, Cash, stage and state words of the game when they change. Release builds do not write it. | The slot log and the upcall log of TASK-E2.2 (`PLAN.md` DES-13). The probe only reads guest memory. The game does not see the file, because the guest can open only the files folder (#3). | E2 |
| 7 | Before the guest writes (`fopen` with mode `w` or `a`), deletes (`unlink`) or replaces (`rename` target) `Save%d.dat`, `Sng%d.dat` or `option.sav`, the bridge copies the old file to `files/arel-backup/<name>.1`. The older copies move to `.2` and `.3`. The bridge does not make a copy that is byte-equal to the newest copy. A failed copy writes a log line and the game continues. | No save loss (`PLAN.md` DES-14, REQ-17). The guest does not see the folder. | E3 |
| 8 | A second launcher entry, "Arel Wars Save Import" (`com.gamevil.nexus2.ArelImport`). The user picks the folder of a v1 save set in the system folder picker (`OPEN_DOCUMENT_TREE`, Android 5 and later). The import checks each file as the game does on load (the size word, the frozen device ID, the checksum). It moves the present save files to `files/arel-backup/import-<time>/`, and copies the new set in through a temporary folder and a rename. After an import, the process stops. Debug builds also import a set from `files/arel-import-in/` (extra `staged`). | The save import (`PLAN.md` DES-14, REQ-16). DES-14 says "the three files of one set". The folder picker takes the whole set in one step, with all slots, so `option.sav` always agrees with the `Save` files. | E3 |
| 9 | The game box is the largest 3:2 box inside the safe area: the window minus the visible system bars and the cutout of the screen. The system bars are hidden (immersive mode). After a swipe, the system bars come back for a short time. `ArelInsets` makes the box on each screen, also on a screen narrower than 3:2. v1 patch `0003-aspect` centres a 3:2 box only on a screen wider than 3:2, and stretches the game on a narrower screen. `ArelInsets` writes the line `box X Y W H window W H safe L T R B` to logcat (tag `ArelInsets`). | Target 35 forces edge-to-edge (`PLAN.md` DES-11, TASK-E5.2). No game pixel goes under a system bar or the cutout. The game keeps its 3:2 aspect on every screen. | E5 |
| 10 | The manifest sets `enableOnBackInvokedCallback`. From API 33, `ArelBack` gets the back gesture and the back button from the system, and gives the activity a back key down and up. Below API 33, the back key arrives as in v1. | Predictive back of target 35 (`PLAN.md` DES-11, TASK-E5.2). The game gets the same key event as in v1. | E5 |
| 11 | From API 30, the offline purchase message ("Purchases are unavailable in this offline version.") is not a system Toast. `ArelNotice` shows the same text for the same time (3.5 s). It uses a view on top of the game box, at the place of the v1 Toast. The view takes no touch. Below API 30, the message is the v1 Toast. | From target 30, the system draws each text Toast. From Android 12, it shows the app icon and a maximum of two lines. The v1 text then showed as "Purchases are unavailable in thi…" (`device-offline`, 2026-11-11). | E5 |
| 12 | `ArelWeb` makes each WebView of the v1 layouts (`android.webkit.WebView` and `com.gamevil.nexus2.ui.UIWebView`) with the same constructor as the inflater. Only if that constructor throws, `ArelWeb` puts an empty `FrameLayout` with the same attributes in its place, and writes a `ArelWeb` log line. The shell then calls `ArelWeb.loadUrl`, which skips a view that is not a WebView (smali patch `0003-webview-surface.patch`: `DRMLicensing`, `SkeletonLauncher`, `Natives$9`). With no WebView, the terms page and the help page are empty. | With no WebView provider (the API 26 `default` AVD image, or WebView disabled or in an update), v1 stops at the start: `MissingWebViewPackageException` in `setContentView` (E6, 2026-11-14). With WebView, the views are the same as in v1. | E6 |
| 13 | `ArelSurface` checks the game `SurfaceView` 500 ms after each resume of the game activity. If the view is shown but has no valid surface, it sets the same window attributes again (a relayout). If 1500 ms after the resume the surface is still not valid, it hides the view and shows it again. With a valid surface it does nothing. | On the API 28 AVD, after a screen lock and unlock, the window had no surface on the app side (`ViewRootImpl.mSurface` not valid), and nothing made a relayout. The v1 GL thread waited for ever for `surfaceCreated`, and the screen stayed black (E6, 2026-11-14). HOME and back recovered it. | E6 |
| 14 | On API 26 only, `ArelInsets.Api26` checks the screen box of the game `SurfaceView` (`mScreenRect`) after each pre-draw update of the view. The right edge must be the left edge plus the width of the view. The bottom edge must be the top edge plus its height. If not, it sets the right box and calls `setParentSpaceRectangle` again (reflection). It writes the logcat line `api26 surface rect fixed L T R B`. On other API levels it does nothing. | Android 8.0 has a bug in `SurfaceView.updateSurface`. When only the position of the view changes, it uses the width and height as the right and bottom edges (`mScreenRect.set(left, top, width, height)`). Android 8.1 fixed it. On a 2400 x 1080 AVD the game box starts at x 327. So the game showed in x 327 to 1620, squeezed (E6, 2026-11-16). v1 has the same bug on Android 8.0 when its box is not at x 0. | E6 |
| 15 | `ArelSound` runs the two sound calls of the guest (`OnSoundPlay` and `OnStopSound` of `eruelwarsUIControllerView`) on one worker thread, in the same order. The worker runs the same v1 code (`NexusSound`). When the game activity pauses, the worker drops the calls in its queue. The smali patch is `shell/patches/emu/smali/0005-sound.patch`. | v1 makes a new `MediaPlayer` for each sound effect on the GL thread, inside `NativeRender`. `MediaPlayer.create` and `release` make blocking binder calls to the media server. In the heaviest battle, frames took up to 192 ms, also on the native `armeabi-v7a` path. With the worker, the maximum frame interval in the bench is 50.6 ms (`docs/PERF.md`, E7). A sound can start some milliseconds later than in v1. | E7 |
| 16 | `ArelPerf` reads the clock before and after each `NativeRender` call. Every 2 seconds it writes two logcat lines with the tag `ArelEmuPerf`: the frame rate, the frame intervals and the time in `NativeRender`. The smali patch is `shell/patches/emu/smali/0004-perf.patch`. Debug and release builds. | The performance bench (`PLAN.md` DES-16, `scripts/bench`). The game does not see it. | E7 |
